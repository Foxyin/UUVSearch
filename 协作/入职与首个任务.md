# 入职与首个任务（第一次开某个角色时用）

> 目的：让一个**全新会话**先“进入角色”，再领任务。两步，别合并。
> 适用：`reviewer` / `experimenter` / `writer` 第一次启动；`owner` 接任同理。

## 0. 为什么要两步

新会话没有本项目的记忆。如果第一句就给任务，它会：
- 用通用套路直接开写（不读你的计划）；
- 把“项目事实”当成你口述的版本（而不是 `docs/STATUS.md`）；
- 分不清自己该写什么、不该写什么。

所以第一步只做“入职”：读文件、复述身份与边界、**不落盘**；第二步才给对象、问题、输出路径。

## 1. 第一步：入职（复制即用）

新会话的 cwd 设为项目根 `C:\Users\17053\Desktop\UUVSearch`。

```text
你是 UUVSearch 项目的 reviewer（审查），角色 ID `reviewer`。这是你第一次入职，先不要写任何文件。

按顺序读：
1. `docs/STATUS.md`
2. `协作/协作规则.md`
3. `协作/角色注册表.md`
4. `协作/角色/reviewer.md`
5. `docs/01-review/2026-11-28-issues-checklist.md`（只需知道它有多少条、怎么编号）
6. `docs/02-plan/plan-2026-11-28.md`（只需知道章节结构）

然后只回 6 行，不要多写：
我是谁：
我这轮的任务：
我可以写：
我不能写：
我读到的当前状态：
我建议先做：

规则：首轮不落盘；不要开始审查；等我给对象和输出路径。
```

**验收**：它回 6 行，且能说出“活跃角色 ≤3、我不改被审对象、评审要标效力”。说错就纠正它，别急着给任务。

## 2. 第二步：给任务（复制即用，已按本项目填好）

它回完 6 行后，再发这一段：

```text
任务：审查 UUVSearch 的计划 v3.2 是否“吃透并吸纳”了两侧审查。

对象（只读，不要改）：
- `docs/02-plan/plan-2026-11-28.md`（v3.2）
- `docs/01-review/2026-11-28-issues-checklist.md`（44 条，A1–F6）
- `docs/00-handoff/UUVSearch-交接-20261127.md`（TAOLUN 交接，只读）

要做四件事：
1. 覆盖矩阵：对 44 条逐条给出「条目 → 计划中的落点（§号/行）→ 判定（已吸纳 / 假落点 / 漏 / 不该吸纳）」。不许抽样，44 条全列。
2. TAOLUN 核对：§5 最小可发表包（检测 3 档、能量 3 档、≥5 图、指标、消融）、§6 三个 Gate 与时间盒、§7 P0、§8 不要做，逐项核对是否被吸纳；漏的列出来。
3. 内部逻辑：矩阵 run 数、能量预算与图规模、主指标（KM/log-rank）与删失、Gate 判据、检测模型与信念更新是否自洽；找出算术错误、定义冲突、不可执行项。
4. 结论：给「必改 / 建议 / 可忽略」三档 + 一句结论（能否进 Phase 0）。

约束：
- 只读文件，不读我的口头总结；我的说法不算证据。
- 证据必须写 `文件:行号`；引用计划原文。
- 不跑代码、不改任何文件、不给“项目行不行”的最终决定。
- 输出：`协作/评审/review-2026-11-29-plan-coverage.md`，文件头 5 行：
  对象 / 任务 / 角色 / 是否借用 / 效力（正式）
- 一轮完成；先给 10 行摘要，再写文件。
```

**验收**：产出文件里有 44 行矩阵 + TAOLUN 核对 + 三档结论；效力标 `正式`。没有 44 行矩阵 = 没做完。

## 3. 入职检查表（它回 6 行时对照）

- [ ] 说得出唯一事实源是 `docs/STATUS.md`，不是角色文档；
- [ ] 说得出自己“只能写 `协作/评审/*`、角色文档、交接、提案、变更日志一行”；
- [ ] 说得出“不改被审对象、不做项目决定”；
- [ ] 说得出“首轮不落盘，等对象和输出路径”；
- [ ] 没有开始写审查意见（写了就打断，让它重来）。

## 4. 常见错误

| 症状 | 处理 |
|---|---|
| 第一句就给任务 | 先收回，发第 1 步；否则它会跳过读文件 |
| 它开始写“项目整体评估” | 提醒：只审指定对象，对象之外只作背景 |
| 它引用“你说过……” | 提醒：以文件为准，口头不算证据 |
| 它只抽样 10 条问题 | 打回：44 条全列，缺一条标“未核” |
| 它直接改计划 | 立即停止；评审只写 `协作/评审/` |
| 它把 provisional 当正式 | 让它改文件头的“效力”行并说明理由 |

## 5. 角色替换与演进机制（用户 2026-11-28 确认）

- **替换**（删一个、建一个）：只改 `协作/角色注册表.md` + 角色文档状态（`retired` / `active`），并在 `协作/变更日志.md` 记一行；**不删历史角色文档**，保留可追溯。
- **接任**：同一角色 ID，换会话/换模型；在角色文档“历任”加一行 + 写 `协作/交接/<role>-YYYYMMDD.md`。**“总讨论2”是 `owner` 的接任者，不是新角色 ID**（显示名叫什么都行，ID 不变）。
- **演进**：角色职责/边界可以改，但改的是 `协作/角色/<role>.md` 与 `协作/协作规则.md`，且必须同时更新注册表；**事实源（STATUS/计划/决策）不因角色变化而变**。
- **新建角色**：先问用户；复制 `协作/角色/_模板.md`，写职责/边界/写权限，再在注册表加一行。活跃角色保持 ≤3。
- **删除角色**：先确认没有未收口的任务；角色文档标 `retired`，不删文件。
