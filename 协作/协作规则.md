# 协作规则（UUVSearch）

> 本文件是协作纪律，**不是项目事实源**。项目事实只看 [`docs/STATUS.md`](../docs/STATUS.md)、[`docs/02-plan/`](../docs/02-plan/)、[`docs/03-decisions/`](../docs/03-decisions/) 和根 [`README.md`](../README.md)。
> 本文件由 `owner` 维护；其他角色要改，写 `协作/提案/`。

## 0. 最短版

1. 角色文档只记职责、边界、工作与交接，不是事实源。
2. 一个文件一个写者；不是自己的文件写 `协作/提案/`，由 `owner` 采纳/拒绝。
3. 角色先做任务分诊：不属于本角色，5 行说明 + 建议角色，不写文件。
4. 首轮不落盘；任务不清先问 1–3 个问题。
5. 一次会话只开一个模式：`discuss` / `review` / `audit` / `handoff`（实验角色另有 `experiment`）。
6. 评审必须标效力：`正式` / `provisional` / `参考`。
7. 角色可跨对话接任，角色 ID 不变；“某某 2”不是新角色。
8. **不自我审查**：写代码的人不审自己的代码，写计划的人不批自己的计划。
9. 先收口再停；任何角色都不宣布“项目完成”，只有用户/`owner` 能。

## 1. 事实源（唯一）

| 内容 | 文件 | 写者 |
|---|---|---|
| 当前状态、下一步、未决问题 | `docs/STATUS.md` | `owner` |
| 研究计划（活文档，带版本号） | `docs/02-plan/plan-2026-11-28.md` | `owner` |
| 用户决策记录 | `docs/03-decisions/2026-11-28-decisions.md` | `owner` |

| 代码 | 分支 `feat/gate1-protocol` | `experimenter`（`owner` 审阅后合并） |

角色文档、讨论、评审、交接**都不是**事实源；事实冲突时以本表为准。

## 2. 四个角色

| ID | 名称 | 一句话 | 状态 |
|---|---|---|---|
| `owner` | 总讨论 / 项目管理 | 维护事实源与计划、分派任务、拍板、对用户汇报 | active |
| `reviewer` | 审查 | 独立审查计划/实验设计/代码/结果解释/论文 claim，给证据与必改项 | active（按需启动） |
| `experimenter` | 实验 | 在 `feat/gate1-protocol` 上实现协议、跑实验、落 CSV，不改计划与结论 | active（按需启动） |
| `writer` | 论文写作 | 在 Gate 3 通过后写稿、做图、排版；不碰实验数据生成 | idle（Gate 3 后启用） |

活跃角色实际 ≤3（`writer` 在 Gate 3 前为 idle）。角色是“帽子”不是人：同一模型、不同会话戴不同帽子。

## 3. 单写者

| 路径 | 写者 |
|---|---|
| `docs/STATUS.md`、`docs/02-plan/*`、`docs/03-decisions/*`、`docs/01-review/*`、`协作/协作规则.md`、`协作/角色注册表.md`、`协作/变更日志.md`、`协作/启动提示词.md` | `owner` |

`experimenter` 想改计划/协议文字 → 写 `协作/提案/`；`reviewer` 永远不改被审对象；`writer` 不重算数字，只用 `results/` 与 `scripts/make_tables.py` 的产物。

## 4. 任务分诊（每个角色开工前）

1. 属于本角色 → 在写边界内做。
2. 不属于 → 只回 5 行：我是谁 / 这是什么任务 / 为什么不属于我 / 该给哪个角色 / 我能否只读协助。**不写文件、不下结论。**
3. 不清楚 → 复述 + 问 1–3 个问题，不写。

## 5. 模式

- `discuss`（讨论）：发散、替代方案、桥接。产出 `协作/讨论/<role>-YYYYMMDD-主题.md`。每条 idea 标：依据（事实/假设）/ 与主线关系 / 可检验点 / 风险。
- `review`（评审）：审一个**指定对象**。产出 `协作/评审/review-YYYYMMDD-主题.md`，文件头 5 行（对象/任务/角色/是否借用/效力），证据用 `文件:行号`、数据、引用。
- `experiment`（实验）：只在 `feat/gate1-protocol` 分支跑；开始前写清 tag、配置、seed 范围、预算；结束产 `results/<tag>/`。跑完只报“做了什么、数字是什么”，解释归 `owner`。
- `audit`（盘点）：资产/文献/代码复用评估；先快速初筛，不跑代码、不删移。
- `handoff`（交接）：写 `协作/交接/<role>-YYYYMMDD.md`，含已完成/未完成/先读什么/别重做/风险。

## 6. 评审效力

- `正式`：审的正是它该审的对象、角色正确 → 可作“门”。
- `provisional`：对象/任务错配，或只是初评 → 保留证据，不作判决。
- `参考`：非正式意见，不作门。

门（Gate）只能由用户 / `owner` 根据 `正式` 评审 + 数据来宣布。

## 7. 标准流转（Gate 流程）

```
用户
 └─ owner：写 brief / 更新 STATUS / 定本轮对象与输出路径
     ├─ experimenter：实现 + 跑 → results/<tag>/ + 报告（不解释）
     ├─ reviewer：审 计划/设计/代码/结果 → 协作/评审/*（标效力）
     └─ owner：据数据 + 正式评审决定 通过 / 修 / 停；更新 STATUS、decisions
          └─ writer（Gate 3 后）：用 results + make_tables 写稿
```

硬规则：
- 一个 Gate 内，`experimenter` 不自行扩大矩阵（加条件、加 seed、加图）；
- `reviewer` 不接受 `experimenter` 的“口头保证”，要看 CSV/config/commit；
- 结果表格必须由 `scripts/make_tables.py` 从 CSV 生成，禁止手填；
- 每个 run 必须留 `commit + config + seed + episodes.csv`，新结果不覆盖旧结果。

## 8. DSH 落地

- 角色 = 一个独立会话（推荐）或 `subagent`。审查角色**用新上下文**，不继承写代码的会话，避免自我确认。
- 主会话（`owner`）用 `subagent` 启动：
  - `name: reviewer` + `prompt: 协作/启动提示词.md 的 B 段 + 本轮对象路径`
  - `name: experimenter` + `prompt: C 段 + 本轮 tag/分支/预算`
- 每个角色的技能权限：
  - `owner`：`multi-role-collab`、`experiment-design`（规划）、`karpathy-guidelines`
  - `reviewer`：`paper-reviewer`、`karpathy-guidelines`、`experiment-design`（只用来对照检查清单）
  - `experimenter`：`karpathy-guidelines`、`experiment-design`（只读其矩阵/预算部分）
  - `writer`：`research-paper-writing`、`latex-academic-publisher`、`academic-plotting`、`topconf-figure`、`paper-reviewer`（自审）
- 技能不是权限：装了技能不等于可以改别人文件，写边界仍按 §3。

## 9. 收口与交接

每次会话停止前：
1. 写完本轮模式的产物；
2. 更新自己的角色文档（状态、当前任务、Done、Open、交接摘要）；
3. 写 `协作/交接/<role>-YYYYMMDD.md`（或角色文档里的交接段）；
4. 在 `协作/变更日志.md` 追加一行；
5. 告诉用户：产出了什么、还剩什么。

会话要删/换模型时，明确说“磁盘上已有什么、下个会话先读哪几个文件”。

## 10. 反模式

- 角色文档变成第二事实源；
- “就这一次”改别人文件；
- 审错对象却当判决；
- 一个会话里 discuss + review + handoff 混写；
- 活跃角色超过 3 个、职责重叠；
- 接任者新建角色 ID；
- 注册表/评审索引过期不更新；
- 角色宣布项目完成；
- 实验角色顺手改计划、审查角色顺手改代码。
