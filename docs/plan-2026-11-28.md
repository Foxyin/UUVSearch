# 计划 v3（2026-11-28，草案待确认）

> 活文档：本文件随实验推进修订。每次修改必须在 §12 变更日志记一行「版本 / 日期 / 改了什么 / 为什么 / 影响哪些 Gate」。最终版以用户确认的版本为准。

## 0. 定位与 RQ

search-only 经验研究，不做 confirm/三态，不并入 TAOLUN 方向 A。

**RQ**：在检测退化（Pd/Pfa、虚警）与能量约束下，学习型搜索（DQN/SAC）何时优于、何时不优于经典搜索（lawnmower / greedy-prob / info-gain）？并给出**边界条件**。

**注意**：这是“边界/失效条件”论文，不是“RL 全面胜出”论文。若最终 lawnmower 仍最好，就写 negative result / benchmark，接受更低 venue（交接文档 §4.1）。

## 1. 可检验假设

| 编号 | 假设 | 若成立说明 | 若不成立说明 |
|---|---|---|---|
| H1 | 确定性检测下，RL 与“A* + 声呐匹配 swath 的覆盖”差距不显著（主要差在导航效率） | 旧 README 的 95% vs 100% 是导航短板，不是搜索能力 | 需要找 RL 的真实优势来源 |
| H2 | Pd 下降 / Pfa 上升时，覆盖型策略的条件 time-to-find 上升更快；信念条件化 RL 上升更慢 | 信念图有价值，且可量化 | RQ 无信号 → Gate 2 止损 |
| H3 | 能量越紧，覆盖冗余的代价越大，RL 的“少走回头路”优势越明显 | 能量是第二个调节变量 | 能耗不是有效变量，降级为次要指标 |
| H4 | 信念观测只在检测退化时带来增益；确定性检测下不增益甚至有害 | 支持“何时需要贝叶斯”的方法论结论 | 信念通道始终有用/始终无用，需重设消融 |

## 2. 环境改造（P0 核心）

### 2.1 检测层：从“确定性发现”改为“带 Pd/Pfa 的采样”

现状：`envs/continuous_env.py:124` `target_detected = self.target_pos_grid in fov_cells` —— 进 FOV 即发现。

改为逐格采样（`config/env/*.yaml` 的 `detection` 段控制，默认仍可切回 deterministic 以复现旧结果）：

```yaml
detection:
  mode: sampled          # deterministic | sampled
  pd_curve: linear       # linear | steep  （linear: 1-0.3d/R；steep: 近距0.95→远距0.5）
  pfa: 0.0               # 0 | 0.02 | 0.05
  pfa_pattern: uniform   # uniform | clustered
  record_events: true
```

- 真目标所在格：`blip ~ Bernoulli(Pd(d))`；命中 → 回合终止（真检出）。
- 其他格：`blip ~ Bernoulli(Pfa)` → **虚警接触**，不终止，但写入事件日志。
- 每个 episode 输出 `events.csv`：step、cell、type(detect/false_alarm/miss)、pd_used、pfa_used。

### 2.2 信念更新：改成 odds 形式，与检测模型一致

现状问题：检测是确定性的，信念却按 `p_detect=1-0.3d/R` 做乘性更新，且未检出时用 `(1-p_detect)` —— 模型与数据生成过程不一致（交接文档 §1.2、§9）。

改为两假设贝叶斯（对 FOV 内每格）：

```
blip    : odds *= Pd / Pfa
no blip : odds *= (1 - Pd) / (1 - Pfa)
```

- 虚警自然抬高该格后验，再次扫过无接触则回落 —— **不需要 confirm 动作**，与 search-only 定位一致。
- 归一化在 free 掩码上做一次（不要全局重复归一化，避开 UUV 那个错误）。
- 观测仍是 4 patch，probability patch 直接放归一化后验（obs 维度不变，488）。

### 2.3 能量

`energy = Σ(直行 1.0 + 转弯 0.5·|Δψ|/45° + 碰撞 1.0)`，单位“等效格”。三档预算 300 / 600 / 1000（≈步数口径），所有方法同预算；同时单独记录 `path_length`。超过预算 → truncate（记 censored）。

## 4. 方法与 baseline

| 类别 | 方法 | 说明 |
|---|---|---|
| 经典 | random | 下界 |
| 经典 | lawnmower（swath = 2R，A* 导航） | 覆盖上界参考；需用声呐宽度匹配的 swath |
| 经典 | greedy_prob | 局部概率贪心（保留，代表“会看概率图但短视”） |
| 经典 | info_gain | **新增**：熵减贪心，1-step lookahead |
| 经典 | bayes_myopic | 全局后验最高点 + A*，代表“贝叶斯但短视” |
| 学习 | DQN / SAC | 同一 obs/action/budget；每配置 ≥3 训练 seed，报全部 seed 均值，不挑最好 |
| 参考 | oracle_TTF | 已知目标位置的最短路径长度，只作下界参考 |

## 5. 指标与统计

- 主指标：**条件 time-to-find**（成功回合的步数/能量），删失率单独报。
- 次指标：成功率、path_length、energy、coverage@detection、false_alarm_contacts、wasted_steps（去查看虚警的步数）。
- 统计：所有方法共用同一 (map, seed) 随机数流（common random numbers）→ 配对比较；条件 TTF 用 paired Wilcoxon signed-rank；中位数差的 95% bootstrap CI。
- 产出：`results/<tag>/episodes.csv`（每回合一行）、`summary.json`、`meta.json`（git commit、配置、seed 集）；README 表由 `scripts/make_tables.py` 从 CSV 生成，不手填。

## 6. 阶段与 Gate

**Phase 0（1–1.5 天，不训练）**
1. 地图工厂参数化 + M1–M5 + 导出 PNG/ASCII。
2. 检测层（sampled/deterministic 开关）+ odds-Bayes + 事件日志 + 能量。
3. `algorithms/info_gain.py`；经典基线导航统一到 `nav.AStarNavigator`。
4. `scripts/run_suite.py`（统一入口、并行 episode、CSV/JSON/meta）+ `make_tables.py`。
5. 用旧 checkpoint 跑 Gate 1 表，核对 README 数字（确认 checkpoint↔表对应）。

**Gate 1（W1）**：7 方法 × 5 图 × 5 seeds = 175 ep/方法，**不训练**。
- 通过标准：方法排名在 5 seeds 下稳定（bootstrap 后名次不翻转），且经典基线达到“A* + 匹配 swath”的合理水平（oracle_coverage 条件 TTF ≈ 30–40）。
- 不通过：先修协议（导航/评估/预算），不加新模型。
- 旧 checkpoint 在 M2–M5 上是分布外，**仅用于协议校准，不作为结论**。

**Gate 2（W2）**：小网格训练，见 §7。
- 通过标准：检测/能量至少一个变量能显著改变方法间排名（配对检验 p<0.05 或效应量 ≥20%）。
- 不通过：换一个 RQ（如“信念观测 vs 覆盖观测”单独成题）再试一周；仍无信号 → 技术报告并停。

**Gate 3（W3）**：边界图（Pd × 能量 的 RL−classical 条件 TTF 差热图）+ 3–5 个失败案例轨迹。
- 有清晰边界或反直觉结论 → 写 4–6 页短稿；否则技术报告，停。

## 7. Gate 2 实验矩阵（42 run）

| 条件 | 检测 | 能量 | obs | 算法 | seeds | run 数 |
|---|---|---|---|---|---|---|
| C0 | deterministic | 600 | belief | DQN,SAC | 3 | 6 |
| C1 | Pd .9 / Pfa 0 | 600 | belief | DQN,SAC | 3 | 6 |
| C2 | Pd .7 / Pfa 0 | 600 | belief | DQN,SAC | 3 | 6 |
| C3 | Pd .5 / Pfa .02（均匀+成簇各一段） | 600 | belief | DQN,SAC | 3 | 6 |
| C3c | 同 C3 | 600 | **coverage-only** | DQN,SAC | 3 | 6 |
| C0c | deterministic | 600 | **coverage-only** | DQN,SAC | 3 | 6 |
| C4 | Pd .7 / Pfa 0 | 300 & 1000 | belief | DQN,SAC | 3 | 6 |

- 每 run 200k 步；训练在 M1（+ M2/M3 轮换做稳健性检查，可选），评估在 M1–M5 × 5 seeds。
- 预算：CPU 8 进程并行，约 35 min/run → 42 run ≈ 3.5 h 墙钟。
- C0c/C3c 是 H4 的关键对照（信念观测 × 检测退化 的 2×2 的一个切面）。

## 8. 消融（Gate 全过后补）

1. 检测模型：deterministic / Pd / Pd+Pfa（Gate 2 已覆盖）。
2. 能量松中紧（Gate 2 已覆盖）。
3. 奖励：现有 reward vs 只保留 find+coverage。
4. 地图规模：14×14 vs 20×20；声呐半径 2/3/4 各一档。
5. Pd 曲线形状：linear vs steep。

- 分支：主线从 `main` 开 `feat/gate1-protocol`；`wip/fair-baselines` 只作参考，可摘取实现思路，不整体合并（它是看交接文档之前的一次独立尝试）。

## 10. 风险与止损

| 风险 | 应对 |
|---|---|
| Pd 采样后旧模型失效 | Gate 2 全部重训；Gate 1 只校准协议 |
| 覆盖率指标掩盖时间信息 | 主指标固定为条件 TTF + 删失率 |
| 结构图生成器耗时 | 先做管线+礁石一种，走廊迷宫可视 Gate 1 结果再补 |
| Phase 0 拖期 | 超 3 天砍能量模块，先保检测+评估 |
| 结果不支持 H2 | 按 Gate 2 止损，不硬拗 |

## 11. 待确认的设计点

1. 虚警语义：按 §2.2 的 odds-Bayes（虚警只抬后验、不终止、不设 confirm 动作）——是否认可？
