> 活文档：本文件随实验推进修订。每次修改必须在 §12 变更日志记一行「版本 / 日期 / 改了什么 / 为什么 / 影响哪些 Gate」。最终版以用户确认的版本为准。

## 0. 定位与 RQ

search-only 经验研究，不做 confirm/三态，不并入 TAOLUN 方向 A。

**RQ**：在检测退化（Pd/Pfa、虚警）与能量约束下，学习型搜索（DQN/SAC）何时优于、何时不优于经典搜索（lawnmower / greedy-prob / info-gain）？并给出**边界条件**。

**注意**：这是“边界/失效条件”论文，不是“RL 全面胜出”论文。若最终 lawnmower 仍最好，就写 negative result / benchmark，接受更低 venue（交接文档 §4.1）。

## 1. 可检验假设

| 编号 | 假设 | 若成立说明 | 若不成立说明 |
|---|---|---|---|
| H1 | 确定性检测下，RL 与“A* + 声呐匹配 swath 的覆盖”差距不显著（主要差在导航效率） | 旧 README 的 95% vs 100% 是导航短板，不是搜索能力 | 需要找 RL 的真实优势来源 |
| H2 | Pd 下降 / Pfa 上升时，覆盖型策略的条件 time-to-find 上升更快；信念条件化 RL 上升更慢 | 信念图有价值，且可量化 | RQ 无信号 → Gate 2 止损 |
| H3 | 能量越紧，覆盖冗余的代价越大，RL 的“少走回头路”优势越明显 | 能量是第二个调节变量 | 能耗不是有效变量，降级为次要指标 |
| H4 | 信念观测只在检测退化时带来增益；确定性检测下不增益甚至有害 | 支持“何时需要贝叶斯”的方法论结论 | 信念通道始终有用/始终无用，需重设消融 |

> **H4 的理论前提**（§2.2 会给出证明/实测）：确定性检测且无虚警时，“未找到目标”意味着目标必在未扫格，后验就是“未扫格上的均匀分布”，与 coverage 通道信息等价；只有引入 Pd<1 或 Pfa>0，回波才携带覆盖之外的新信息。因此 H4 不是拍脑袋——它是“信念是否有信息量”的必要条件检验。

## 2. 环境改造（P0 核心）

### 2.1 检测层：从“确定性发现”改为“带 Pd/Pfa 的采样”

现状：`envs/continuous_env.py:124` `target_detected = self.target_pos_grid in fov_cells` —— 进 FOV 即发现。

改为逐格采样（`config/env/*.yaml` 的 `detection` 段控制，默认仍可切回 deterministic 以复现旧结果）：

```yaml
detection:
  mode: sampled          # deterministic | sampled
  pd_curve: linear       # linear | steep  （linear: 1-0.3d/R；steep: 近距0.95→远距0.5）
  pfa: 0.0               # 0 | 0.02 | 0.05
  pfa_pattern: uniform   # uniform | clustered
  record_events: true
```

- 真目标所在格：`blip ~ Bernoulli(Pd(d))`；命中 → 回合终止（真检出）。
- 其他**自由格**：`blip ~ Bernoulli(Pfa)` → **虚警接触**，不终止，但写入事件日志。障碍格不产生回波（否则等于免费获得地图）。
- 每个 episode 输出 `events.csv`：step、cell、type(detect/false_alarm/miss)、pd_used、pfa_used。

**必须写进论文的建模假设（避免审稿人误解）**：

1. **回波独立**：同一格每次扫过的 blip 独立同分布（i.i.d.），不随停留时间累积；这是“单次探测”模型，不是“持续照射”。
2. **无分类错误**：真目标格一旦产生回波即判为“检出/成功”，不再区分“真目标回波”与“恰好在目标格发生的虚警”。等价于假设虚警只发生在非目标格——这是简化，论文 limitation 要写。
3. **虚警不改变地图**：虚警只是观测事件，不生成假目标实体；信念图靠再次扫过无回波自行回落。
4. **Pd 只依赖距离**，不依赖方位/海底底质；Pd 曲线形状（linear/steep）作为消融。

### 2.2 信念更新：改成 odds 形式，与检测模型一致

现状问题：检测是确定性的，信念却按 `p_detect=1-0.3d/R` 做乘性更新，且未检出时用 `(1-p_detect)` —— 模型与数据生成过程不一致（交接文档 §1.2、§9）。

改为两假设贝叶斯（对 FOV 内每格）：

```
blip    : odds *= Pd / Pfa
no blip : odds *= (1 - Pd) / (1 - Pfa)
```

- 虚警自然抬高该格后验，再次扫过无接触则回落 —— **不需要 confirm 动作**，与 search-only 定位一致。
- 归一化在 free 掩码上做一次（不要全局重复归一化，避开 UUV 那个错误）。
- 观测仍是 4 patch，probability patch 直接放归一化后验（obs 维度不变，488）。

**确定性档也必须自洽**：`mode=deterministic` 时不能再用 `(1-Pd)` 软更新，正确更新是「扫过的自由格后验置 0，未扫格保持均匀，再归一化」。否则信念图与数据生成过程矛盾（这正是旧代码的 A2 问题）。

**推论（H4 的前提，也是 C0/C0c 对照的合法性依据）**：确定性、无虚警时，后验 = 未扫格上的均匀分布 = `1 - coverage`（在 free 掩码上），因此 probability patch 与 uncertainty patch 完全共线；此时“信念观测 vs 覆盖观测”在信息上等价，两种网络看到的输入只差一个确定性变换。所以：

- C0 与 C0c 的差异**应当不显著**（信息等价，只剩优化层面的噪声）；若出现显著差异，先查实现（patch 拼装/归一化），再用多 seed 判断是不是纯训练噪声 —— 这是我们的一条**负向自检**。
- 旧版 488 维观测在确定性检测下，coverage / uncertainty / probability 三个 patch 高度共线，实际有效信息远少于 488 维；这一点直接支撑论文的动机段（“为什么现在的信念通道学不到东西”）。

### 2.3 能量

`energy = Σ(直行 1.0 + 转弯 0.5·|Δψ|/45° + 碰撞 1.0)`，单位“等效格”。

**预算按地图自由格数归一化**，而不是绝对步数——否则 14×14 的 300 步到 20×20 上等于没给预算，跨图对比就失效：

| 档 | 预算 | M1（178 自由格） | 20×20（≈340 自由格） |
|---|---|---|---|
| 紧 | 1.5 × free_cells | 267 | 510 |
| 中 | 2.5 × free_cells | 445 | 850 |
| 松 | 4.0 × free_cells | 712 | 1360 |

所有方法同预算；同时单独记录 `path_length` 与 `energy_used`。超过预算 → truncate（记 censored）；为防止死循环，`max_steps = ceil(2 × budget)` 作为硬上限，触顶也记 censored。

**能量是约束，不进奖励**：奖励函数保持原样（每步 −0.05 已经隐含时间成本），避免“步数惩罚 + 能量预算”双重计数，也避免 C0/C1 与 C4 之间奖励口径变化。能量只用于终止条件和评价指标。

### 2.4 观测层：冗余通道与特权信息

现状观测 = 4 patch（coverage / uncertainty / probability / obstacle）× 121 + 4 维状态。

- **uncertainty ≡ 1 − coverage**：`info_map.uncertainty_decay = 1.0`，扫描后不确定度永久归零、永不恢复，所以该通道是 coverage 的线性函数，121 维纯冗余。
  - 处置：保留 488 维不变（可比性），但加配置 `obs.uncertainty: coverage | entropy`（`entropy` 用归一化后验熵，语义变成“我还不知道该去哪儿”）。Gate 2 主矩阵用 `coverage` 与旧模型对齐；Gate 2 之后补一组 `entropy` 消融。
- **obstacle patch 是特权信息**：11×11 视野（半径 5）远大于声呐半径 3，等于给了 RL 超出传感器的避障地图。
  - 处置：配置 `obs.obstacle: full | sonar_limited`（`sonar_limited` 把 patch 限制在半径 R 内，其余置 0）；主矩阵保持 `full` 以便与旧结果对比，论文 limitation 明写“RL 用了短程特权避障通道”，并补一组 `sonar_limited` 消融。
- 概率 patch 直接放 §2.2 的归一化后验。
- **coverage-only 观测（C0c/C3c）的精确定义**：probability patch 全置 0，其余 3 个 patch 与状态不变（维度仍 488）。这样两组网络的容量、输入尺度完全一致，唯一差别就是“有没有信念通道”。
  - 注意：确定性档下 probability 与 uncertainty 共线（§2.2 推论），C0 与 C0c 理论上等价；`Pfa>0` 时 probability patch 不再是 coverage 的函数（假峰、回落），此时两种观测才真正不同。

### 2.5 运动学与碰撞口径（影响所有方法的公平性）

- **动作 1 步滞后**：`envs/auv_model.py` 先用旧 `psi` 移动、再更新 `psi`，所以 t 时刻的动作作用在 t+1 的位移上。这是实现事实，不是 bug；保留以维持可比性，论文环境描述里必须写明（否则读者会误以为动作即时生效）。
- **碰撞处理**：现状是“回到原位 + 随机 ±90–180° 旋转 + 罚分”。随机旋转会引入不可控噪声，且卡在障碍口袋时会连锁碰撞（审计里 oracle 基线 9.7 次/回合 vs RL 3–4 次）。
  - 处置：加配置 `collision.rotate: random | deterministic`（`deterministic` = 固定 +90°），主矩阵沿用 `random`（与旧环境一致）；Gate 3 补一组 `deterministic` 敏感性，确认结论不依赖碰撞噪声。

### 2.6 P1 扩展（P0 不做，Gate 过后视结果决定）

- 信息先验（目标更可能在管线/航道附近）：先验非均匀时信念图才有“先验 × 证据”的用武之地，是 H4 的加强版。
- 可移植 AUV `src/uuv_framework/sonar/noise.py` 的噪声/衰减算子（需重接 beam→cell 接口，工作量大）。
- 移动目标、多目标：会改变任务定义，不属于 search-only 最小包。

## 4. 方法与 baseline

| 类别 | 方法 | 说明 |
|---|---|---|
| 经典 | random | 下界 |
| 经典 | lawnmower（oracle，swath=2R + A*） | 用**完整地图**算路线，是覆盖能力的上界参考，不是公平对手；论文里标 `oracle` |
| 经典 | online_lawnmower | **新增**：只用“已确认自由格”做 boustrophedon，遇到未知/障碍就地 A* 重规划；不需要完整地图，是**公平的强覆盖基线** |
| 经典 | greedy_prob | 局部 11×11 概率贪心（保留，代表“会看概率图但短视”；用了局部真值可通行掩码，标 `privileged`） |
| 经典 | info_gain | **新增**：熵减贪心，对 5 个动作做 1-step 期望后验熵最小化 |
| 经典 | bayes_myopic | 全局后验最高点 + A*，代表“贝叶斯但短视” |
| 学习 | DQN / SAC | 同一 obs/action/budget；每配置 ≥3 训练 seed，报全部 seed 均值，不挑最好 |
| 参考 | oracle_TTF | 已知目标位置的最短路径长度，只作下界参考（不参与排名） |

> 关键区分：`lawnmower` 是 oracle（有全图），`online_lawnmower` 才是和 RL 同等信息的经典对手。旧审计里“RL 接近覆盖上界”的说法之所以站不住，一半是 swath 不匹配，另一半就是没有这个 online 对手。

## 5. 指标与统计

- 主指标：**time-to-find（TTF）**，按能量/步数计；同时报“条件 TTF”（仅成功回合）与**删失率**。
- 注意：只对成功回合求平均是有偏的（长度偏差：难的回合被剔除，会把方法显得更快）。因此：
  - 主统计用**生存分析**：Kaplan–Meier 中位 TTF + log-rank 检验（删失按右删失处理）。
  - 条件 TTF 只作描述性报告，且必须同时给 n（成功回合数）。
- 次指标：成功率、path_length、energy_used、coverage@detection、false_alarm_contacts、wasted_steps（去查看假峰浪费的步数）。
- 配对比较：所有方法共用同一 (map, seed) 的靶点/起点/回波随机流（common random numbers）。只有在“两方法都成功”的回合上做 paired Wilcoxon，并报配对数 n；因删失导致的样本损失在表注里写清楚。
- 多重比较：Gate 2 的多条件对比用 Holm 校正后再看 p<0.05。
- 产出：`results/<tag>/episodes.csv`（每回合一行，含 censored 标志与删失原因）、`summary.json`、`meta.json`（git commit、配置全文、seed 集）；README 表由 `scripts/make_tables.py` 从 CSV 生成，不手填。

## 6. 阶段与 Gate

**Phase 0（2–3 天，不训练）**
1. 地图工厂参数化 + M1–M5 + 导出 PNG/ASCII。
2. 检测层（sampled/deterministic 开关）+ odds-Bayes + 事件日志 + 能量（按 free_cells 归一化预算）。
3. `algorithms/info_gain.py`、`algorithms/online_lawnmower.py`；经典基线导航统一到 `nav.AStarNavigator`。
4. `scripts/run_suite.py`（统一入口、并行 episode、CSV/JSON/meta）+ `make_tables.py`。
5. 用旧 checkpoint 跑 Gate 1 表，核对 README 数字（确认 checkpoint↔表对应）。

**Gate 1（W1）**：6 个经典方法（含 online_lawnmower）× 5 图 × 5 seeds = **25 ep/方法**（合计 150 回合），**不训练**。
- 通过标准（两条都满足）：
  1. **排名稳定**：5 seeds 重采样后，任一方法的排名不翻转（bootstrap 名次区间不跨位次）。
  2. **覆盖基线可信**：每张图上 `oracle_coverage` 的条件 TTF ≤ 1.3 × 该图的 `oracle_TTF` 下界（按图各自算，不用统一的 30–40 步）。
- 不通过：先修协议（导航/评估/预算），不加新模型。
- 旧 checkpoint 在 M2–M5 上是分布外，**仅用于协议校准，不作为结论**。

**Gate 2（W2）**：训练网格，见 §7。
- 通过标准：检测/能量至少一个变量能显著改变方法间排名（Holm 校正后 log-rank p<0.05，且中位 TTF 差 ≥20%）。
- 不通过：换一个 RQ（如“信念观测 vs 覆盖观测”单独成题）再试一周；仍无信号 → 技术报告并停。

**Gate 3（W3）**：边界图（Pd × 能量 的 RL−classical 条件 TTF 差热图）+ 3–5 个失败案例轨迹。
- 有清晰边界或反直觉结论 → 写 4–6 页短稿；否则技术报告，停。

## 7. Gate 2 实验矩阵（48 run）

能量列用“× free_cells”表示（M1 上 = 267/445/712；见 §2.3）。

| 条件 | 检测 | 能量 | obs | 算法 | seeds | run 数 |
|---|---|---|---|---|---|---|
| C0 | deterministic | 2.5× | belief | DQN,SAC | 3 | 6 |
| C0c | deterministic | 2.5× | coverage-only | DQN,SAC | 3 | 6 |
| C1 | Pd .9 / Pfa 0 | 2.5× | belief | DQN,SAC | 3 | 6 |
| C2 | Pd .7 / Pfa 0 | 2.5× | belief | DQN,SAC | 3 | 6 |
| C3 | Pd .5 / Pfa .02（均匀） | 2.5× | belief | DQN,SAC | 3 | 6 |
| C3c | Pd .5 / Pfa .02（均匀） | 2.5× | coverage-only | DQN,SAC | 3 | 6 |
| C4 | Pd .7 / Pfa 0 | 1.5× 与 4× | belief | DQN,SAC | 3 | 12 |

- 合计 **48 run**。每 run 200k 步；训练只用 M1（用户 2026-11-28 定），评估在 M1–M5 × 5 seeds。
- C4 是 H3 的能量维度（两档 × 2 算法 × 3 seed）。
- C0 vs C0c 是**负向自检**：确定性下两者信息等价，若差异显著说明实现/训练有问题。
- **成簇虚警（clustered Pfa）不进主矩阵**，放 Gate 3 敏感性（6 run），避免矩阵再膨胀。
- 预算：CPU 8 进程并行，约 35 min/run → 48 run ≈ 3.5–4 h 墙钟；评估（48 run × 25 回合）再约 1 h。
- 若 Gate 2 有信号，再用 M1–M3 轮换补一轮稳健性（用户已同意“先 M1，后面再做 1–3”）。

## 8. 消融（Gate 全过后补）

1. 检测模型：deterministic / Pd / Pd+Pfa（Gate 2 已覆盖）。
2. 能量松中紧（Gate 2 已覆盖）。
3. 奖励：现有 reward vs 只保留 find+coverage。
4. 地图规模：14×14 vs 20×20；声呐半径 2/3/4 各一档。
5. Pd 曲线形状：linear vs steep。
6. 观测通道：`uncertainty = coverage | entropy`、`obstacle = full | sonar_limited`（回答“冗余 121 维是否拖累学习”和“特权避障贡献多少”）。
7. 碰撞口径：`random` vs `deterministic` 旋转（结论稳健性检查）。
8. 虚警成簇（Gate 3 敏感性，6 run）与“虚警额外惩罚”B 方案（2 run，可选，只作讨论用）。
9. 经典基线的信息量阶梯：random < online_lawnmower（无全图） < lawnmower（全图 oracle）——用来定位 RL 落在哪一档。

## 9. 工程与复现

- 分支：主线从 `main` 开 `feat/gate1-protocol`；`wip/fair-baselines` 只作参考，可摘取实现思路，不整体合并（它是看交接文档之前的一次独立尝试）。
- 一条命令：`python scripts/run_suite.py --suite gate1 --config config/suites/gate1.yaml`
- **seed 纪律**：一个 `--seed` 同时设 `np.random`、`random`、`torch`、env `reset(seed=)`、replay buffer；禁止只设一部分。每回合 `seed = base_seed + episode`，方法间共用同一 seed 序列（common random numbers）。
- **checkpoint 口径**：同时评估 `best.pt` 与 `final/step_*.pt`；`best.pt` 是按训练 success_rate 选的，SAC 存在训练/评估结构性 gap，不能只报一个。
- 评估与绘图分离：Evaluator 不再每步重算 FOV 画图，轨迹/热图单独出。
- 每条结果写 `meta.json`（git commit、config 全文、seed 集、运行时间）；历史结果不覆盖，新结果进 `results/<date>-<tag>/`。
- 训练日志进 TensorBoard（`experiments/logs/`），浏览器看曲线。
- **旧数字撤回**：README/CLAUDE.md 里“DQN 95% / SAC 94% 优于 Lawnmower”的表述作废（那是导航短板 + 不同口径 + 单 seed），统一改为“历史记录，已被 2026-11-27 审计推翻”。

## 10. 风险与止损

| 风险 | 应对 |
|---|---|
| Pd 采样后旧模型失效 | Gate 2 全部重训；Gate 1 只校准协议 |
| 覆盖率指标掩盖时间信息 | 主指标改为 TTF（KM 中位 + 删失率），不用条件均值单独下结论 |
| 删失回合多、配对样本变少 | 主检验用 log-rank（不要求配对）；配对 Wilcoxon 只作辅助并报 n |
| 结构图生成器耗时 | 先做管线+礁石一种，走廊迷宫可视 Gate 1 结果再补 |
| Phase 0 拖期 | 超 3 天砍能量模块，先保检测+评估 |
| RL 学出保守策略（躲 Pfa 区、少探索） | 用 coverage@detection 和 wasted_steps 诊断；若覆盖率显著低于经典基线，判为学习失败而不是“RL 不行” |
| 结果不支持 H2 | 按 Gate 2 止损，不硬拗 |
