# Scientific Storytelling & Narrative Assessment Framework

Synthesized from Joshua Schimel's *Writing Science*, Nature Nanotechnology editorials,
and published writing-quality assessment rubrics.

---

## Core Principle

A scientific paper should make the reader experience the same "moment of epiphany"
the authors felt. Data, figures, and models are the "characters" in the story.
The key is to **show, don't tell**.

---

## The OCAR Structure (Opening-Challenge-Action-Resolution)

Maps onto IMRaD:

| OCAR Element | IMRaD Section | What it does |
|-------------|---------------|-------------|
| **Opening** | Introduction (first half) | Introduce the larger problem/field. Why should anyone care? |
| **Challenge** | Introduction (second half) | Pose the specific question. What is the unresolved gap? |
| **Action** | Methods + Results | Describe what was done and what was found |
| **Resolution** | Discussion + Conclusion | Explain what it means, how the gap is filled, what comes next |

### The Hourglass Rule

```
Opening  ████████████████  (wide — field-level importance)
         ████████████████
          ██████████████
Challenge   ██████████      (narrow — specific gap/question)
             ██████
Action       ██████        (narrowest — what was done)
             ██████
            ██████████
Resolution ██████████████   (widening back — implications)
          ████████████████
Conclusion ████████████████ (wide — field-level impact)
```

**Critical check**: The Opening width MUST match the Resolution width.
- Opening wider than Resolution → overpromising, "cheating" the reader
- Opening narrower than Resolution → underpromising, lost audience

## The SUCCESS Framework for "Sticky" Scientific Stories

| Element | What it means | Red flag if missing |
|---------|--------------|-------------------|
| **S**imple | Core idea captured compactly | Rambling, multiple competing themes |
| **U**nexpected | Goes beyond incremental science | "We all knew this was coming" |
| **C**oncrete | Specific, definite descriptions | Vague claims, no numbers |
| **C**redible | Believable; evidence matches claims | Overclaiming, missing evidence |
| **E**motional | Evokes curiosity and excitement | Dry, unengaging prose |
| **S**tories | Modular story units threaded together | Disconnected sections, broken arcs |

## Narrative Arc Assessment Per Section

### Abstract
```
Context/Problem → Gap → Approach → Key Result → Implication → Boundary
```
**Red flags**: Missing quantitative results, overclaiming in final sentence, no boundary stated.

### Introduction
```
Field scale → Bottleneck → Prior attempts → Unresolved gap → Present study
```
**Red flags**: Literature review as paper-by-paper list (not synthesis), no clear gap statement,
final paragraph doesn't state what THIS paper does.

### Related Work
```
Topic synthesis (not paper list) → How prior work relates → What remains unsolved
```
**Red flags**: "Smith et al. [1] did X. Jones et al. [2] did Y. Wang et al. [3] did Z."
No synthesis, no positioning of the current work.

### Methods
```
Module motivation → Module design → Forward process → Technical advantage
```
**Red flags**: No motivation for design choices ("we used X because..."), recipe-style
without explaining WHY each step.

### Results
```
Evidence ladder (not chronological lab diary) — build from simple to complex,
each result setting up the next question.
```
**Red flags**: Results presented in order of execution, not logical order. No narrative
thread connecting findings.

### Discussion
```
Explain meaning → Relate to prior work → Acknowledge constraints → Future directions
```
**Red flags**: Repeating results instead of interpreting them. Overclaiming.
No comparison to prior work. No limitations acknowledged.

### Conclusion
```
What was done → What was found → What it means → What comes next (bounded)
```
**Red flags**: Introducing new material. Generic "more research is needed."
Excessive hedging that undermines the contribution.

## Broken Arc Detection

A "broken arc" occurs when an idea is discussed in multiple disconnected places
without a clear thread. Check:

1. **Cross-reference consistency**: Does Section 3's claim match Section 5's evidence?
2. **Promise-delivery gap**: Does the Introduction promise what the Results deliver?
3. **Abstract-body gap**: Do numbers in the abstract match numbers in the body?
4. **Figure-text gap**: Does the text accurately describe what the figure shows?
5. **Introduction-conclusion width match**: Does the conclusion return to the opening's scope?

## What Kills a Scientific Story

| Pattern | Example | Why it's bad |
|---------|---------|-------------|
| **Hyperbole** | "breakthrough", "paradigm shift", "groundbreaking" | Undermines credibility; doubled in 50 years |
| **Hiding negative results** | Only best-case shown | Non-scientific bias; reviewer will find the gaps |
| **Overpromising** | Introduction claims "all X" but experiments cover "one Y" | Reviewer's first rejection reason |
| **Distracting resolution** | Conclusion introduces new claims not in Results | Feels dishonest |
| **"More research is needed"** | Generic closer without specifics | Wastes the conclusion's most valuable real estate |
| **Noun chunk chains** | 3+ consecutive nouns: "underwater vehicle propulsion fault diagnosis" | Unreadable |

## Flow Assessment: Paragraph-Level

For each paragraph, ask:
1. **What is the ONE message?** (If more than one, split.)
2. **Is the topic sentence first?** (If buried, restructure.)
3. **Does every sentence earn its place?** (If a sentence is removed, is anything lost?)
4. **How does this paragraph connect to the previous one?** (If no explicit or implicit link, add a transition.)
5. **Does the paragraph end with a bridge to the next?** (Not mandatory, but helps flow.)

## Quantifiable Writing Quality Metrics

From analysis of 130 peer-reviewed abstracts (correlated with citations):

| Component | Direction of quality |
|-----------|-------------------|
| Shorter abstracts | Higher citations |
| First person ("we", "I") | Higher influence |
| Cause/effect conjunctions ("therefore", "because") | Better flow |
| Signposts ("first", "then", "finally") | Better clarity |
| Colons and semicolons | Link ideas (use sparingly in SCI) |
| Consistent key terms (not synonym cycling) | Better clarity |
| Fewer acronyms | Better readability |
| Fewer 3+ noun chains | Better readability |
